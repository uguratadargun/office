## 4. Human-only steps (nobody else can do these)

1. **Decide the two workflows in §3** (`blog.yml` keep / `contributor-role.yml` delete)
   and whether `docs/wall-data.json` stays on the site. Neither blocks the tag.
2. **Optional secrets.** None are required for a green unsigned release. Set only if wanted:
   `POSTHOG_KEY` / `POSTHOG_HOST` (analytics; unset = compiled-in `''`, no-op).
   Do **not** set `APPLE_CERTIFICATE_P12` without also setting `APPLE_CERTIFICATE_PASSWORD`
   — electron-builder then imports the p12 with an empty password and hard-fails
   "MAC verification failed".
3. **Dry run first:** Actions → Release → *Run workflow* on `main`. Builds all three
   platforms, publishes nothing. Confirm three green matrix legs.
4. **Tag and push** — this is the release:
   ```
   git tag v0.4.5 && git push origin v0.4.5
   ```
   A tag with a suffix (`v0.4.5-rc.1`) publishes as a **pre-release**, which the in-app
   updater's `/releases/latest` poll deliberately ignores. Use that for a test run.
5. **After it publishes:** `npm run check:links -- --online` against the live release, and
   download the DMG on a machine that has never run the app to confirm the Gatekeeper
   instructions in `RELEASE.md` are the ones users actually need.

## 5. Draft — `## What's new in 0.4.5`

> *Draft. 59 CHANGELOG bullets, grouped by what a user would notice. Paste under the
> heading in `RELEASE.md`, keep the existing `### The first five minutes` / `### Everything
> else` scaffolding around it.*

**The app is called Office.** Window, dock, menus, installer, and the artifact names
themselves. The old `munderdifflin://` links keep working forever, and an existing
profile is adopted on first launch — nobody starts from a factory-fresh app.

**The office runs itself while you are away.**
- Idle agents go to sleep after a configurable delay and wake the moment work arrives.
- An agent's conversation is cleared when its card is signed off, so the next card
  starts on a clean context — and its usage readout resets with it.
- Questions that need a human reach you on **Telegram**, and your reply answers the
  agent. You can run the whole office from the bot.
- **Slack over Socket Mode** — the bridge no longer needs a public URL, and the public
  URL it does open now survives a restart.
- Idle agents occasionally bring Michael a cup of tea.

**Issues, pull requests, and reviews are a loop now.**
- Issues and PRs are two separate tabs.
- A main-process watcher polls `gh`/`glab`, so an issue becomes a PR becomes a review
  without anyone babysitting it. GitLab is at parity, red pipelines link the failing job.
- Michael reviews a PR's diff locally from the Issues tab; agents can act on a PR
  rather than just being told to.

**You can see what things cost.** Per-agent tokens and cost for every engine, not just
Claude — OpenCode and the rest report real numbers. The budget meter is hidden unless
you actually set a budget, and the floor stops paying for turns that carry no news.

**Control over each agent.** Per-agent reasoning effort from the Monitor tab, a
"Working on" line in the detail panel, archived agents can be brought back, kanban cards
can be archived, and every prompt ever submitted is in a command-history panel.

**Settings grew up.** Searchable, behaves like a real dialog, and a **Provider Doctor**
that checks the flags, model ids and env vars each engine actually needs. The boss has
a name you can change.

**One policy for destructive actions, with undo** — replacing five different answers to
"are you sure?".

**Fixed** — sleeping agents come back to the fullscreen view; the context gauge zeroes
on engines whose clear verb is not `/clear`; "Sleep idle agents after" and the other
blur-saved Advanced settings read back what you set; MCP servers reach Crush, Codex and
OpenCode; voice hire spawns the engine you asked for; Kimi and qwen no longer spawn with
flags they do not have; two silent data-loss paths on the way out of a form.

**Removed** — the organisation/teammate messaging UI, which advertised a transport that
does not exist, and three dead IPC clusters.

**Not exercised, and why.** Boss-name labels, hibernate sleep→wake, and clear-on-done
are GUI-interaction paths that need a live hive with spawned `claude` agents; running
them would have meant driving the human's live app and billing his subscription. They
stay covered by `test/boss-name.test.cjs`, `test/idle-hibernate.test.cjs` and
`test/clear-on-done.test.cjs`. The macOS `open-url` half of the deep link (LaunchServices
→ registered app) is also untested: registering the scratch build would have pointed
`office://` at it system-wide for the human. `handleHireLink` is the shared destination
of both routes, so what is untested is only the OS plumbing, and the Info.plist row above
is the packaging half of that.

**Two incidental findings, neither a blocker.**
1. macOS's case-insensitive filesystem makes the packaged profile (`…/Application
   Support/Office`, from `productName`) and the dev profile (`…/office`, from
   package.json `name`) **the same directory**. Dev and a packaged build share one
   profile and one single-instance lock — launching the packaged app while
   `electron-vite dev` runs silently quits.
2. `planUserDataMigration` runs against `app.getPath('appData')`, which ignores `$HOME`
   on macOS. Anyone launching with a custom `--user-data-dir` gets an empty "current",
   so the migration will **move** a legacy `Munder Difflin` profile into that scratch
   dir. Harmless for normal launches; worth knowing before debugging with a throwaway
   profile.
